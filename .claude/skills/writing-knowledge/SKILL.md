# writing-knowledge

書くたびに賢くなる執筆メモリ。
**書く前に読む → 書く → 書いた後に残す → 反応を追記する** の 4 段で回す。

## 保存先（保管庫）の決め方

次の順で決める。最初に当てはまったものを使う。

1. 環境変数 `OBSIDIAN_VAULT` が設定されていれば、そのパス
2. プロジェクトルートに `40_表現ルール/` フォルダがあれば、プロジェクトルート（このリポジトリ自体が保管庫）
3. 隣のフォルダ `../second-brain/` に `40_表現ルール/` があれば、そこ
4. どれもなければ、非公開リポジトリ `michiyosi/second-brain` を `../second-brain/` に clone してから、そこに書く
   - クラウド環境（Claude Code on the web）では、先に `add_repo`（owner: michiyosi, repo: second-brain, access: push）を呼んでから clone する
   - clone できなければ、ユーザーにその旨を伝えて `<プロジェクトルート>/brain/` に一時保存する（公開リポジトリなら注意を添える）

3 と 4 の場合、書き込み後に **必ず `../second-brain/` で git commit と push をする**（`git pull --rebase` してから push）。
コミットメッセージは「brain: <何を記録したか>」の形にする。

## サブコマンド

| 呼び方 | いつ | 動作 |
|---|---|---|
| `/writing-knowledge before <媒体> <テーマ>` | 書く前 | 過去ノートを読み、執筆ブリーフを出す |
| `/writing-knowledge after <記事のパス or 本文>` | 書いた後 | ナレッジノートを作り、index を更新 |
| `/writing-knowledge result <ノート名> <反応>` | 公開後 | 閲覧数・スキ・売上・問い合わせなどを追記 |
| `/writing-knowledge guide` | 随時 | ノートを横断してスタイルガイドを更新 |

## 自動で動くとき

- note 記事、ブログ、LP、メルマガなど **800 文字以上の文章を書く依頼**を受けたら、書き始める前に **before** を実行する（他の執筆スキルを使う場合も、その前に実行する）
- その文章を書き終えて提出したら、続けて **after** を実行する
- ユーザーが「あの記事は反応が良かった」「売れた」「問い合わせが来た」と言ったら **result** を実行する
- ノートが 5 本以上あり、スタイルガイドが 2 週間以上更新されていなければ **guide** を提案する

## before の手順

1. `_index.md` を読む。なければ「初回なのでナレッジなし」と伝えて 4 へ
2. 同じ媒体、近いテーマ、反応が良かったものを優先して、ノートを最大 3 本読む
3. `_スタイルガイド.md` と `40_表現ルール/` の 2 ファイルを読む
4. 次の形式で **執筆ブリーフ** を出し、ユーザーの確認を待たずに執筆へ進む

```markdown
## 執筆ブリーフ
- 媒体 / テーマ:
- 参考にしたノート: [[…]] [[…]]
- 今回使う構成: （見出しの骨組み）
- トーン: （語尾、一人称、硬さ）
- 使う言い回し: （良い表現リストと過去ノートから 3 つ）
- 避けること: （NG リストと過去の反省から）
- CTA / 着地点:
```

## after の手順

1. 書いた本文を読み直し、次のテンプレートでノートを作る
2. `_index.md` の表に 1 行追加する
3. ノートのパスを 1 行で報告する

### ナレッジノートのテンプレート

```markdown
---
title: <記事タイトル>
type: writing
media: note | blog | lp | mail | book
theme: <テーマ>
target: <想定読者>
created: YYYY-MM-DD
published: 未 | YYYY-MM-DD
result: 未計測
tags: [執筆, <媒体>, <テーマ>]
---

# <記事タイトル>

> [!summary] 要点
> 何を、誰に、どんな切り口で書いたか。3 行以内。

## 構成

| 順 | 見出し | 役割 |
|---|---|---|
| 1 | | 導入・問題提起 |
| 2 | | |

## トーンと文体

- 一人称 / 語尾 / 硬さ:
- 意識したこと:

## 使った言い回し

- 「…」（どこで、なぜ効いたか）

## 次回への反省

> [!warning]
> 書きにくかった点、ユーザーから直された点

## 反応

| 日付 | 指標 | 値 | メモ |
|---|---|---|---|

## 関連

- [[_index]] / [[_スタイルガイド]]
```

### _index.md の表（4 列）

```markdown
| 日付 | 媒体 / テーマ | 反応 | ノート |
|---|---|---|---|
| 2026-09-03 | note / トレーラーハウスの税金 | 未計測 | [[2026-09-03_note_トレーラーハウスの税金]] |
```

## result の手順

1. 該当ノートの「反応」表に 1 行追加し、フロントマターの `result` を更新する
2. `_index.md` の「反応」列を更新する
3. 反応が良かった場合は `_スタイルガイド.md` の「効いたパターン」に 1 行追加する

## guide の手順

`30_ナレッジ/執筆/` の全ノートを読み、次の構成で `_スタイルガイド.md` を書き直す。
反応の良かったノートの共通点を優先する。

```markdown
# 執筆スタイルガイド

> [!summary] 要点
> これまでの N 本から抽出した、このユーザーの書き方。

## 基本トーン
## 効いたパターン（反応が良かった共通点）
## 定番の構成
## 避けること
## 媒体別メモ
```

## 終わったら

作成・更新したファイルのパスを 1 行で報告する。
保存先が `brain/` の場合はコミットして push し、その旨も報告する。
