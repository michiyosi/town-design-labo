# obsidian-memo

人間が読みやすい Markdown メモを保管庫に保存する。

## 保存先（保管庫）の決め方

次の順で決める。最初に当てはまったものを使う。

1. 環境変数 `OBSIDIAN_VAULT` が設定されていれば、そのパス
2. プロジェクトルートに `40_表現ルール/` フォルダがあれば、プロジェクトルート（ローカルの Obsidian 保管庫）
3. どちらもなければ `<プロジェクトルート>/brain/`（クラウド環境用）。なければ作成し、`00_Inbox/` `10_スキル一覧/` `20_日報/` `30_ナレッジ/` `40_表現ルール/` も作る

3 の場合、このコンテナは使い捨てなので **書き込み後に必ず git でコミットして push する**。コミットしないと消える。コミットメッセージは「brain: <何を記録したか>」の形にする。

## 手順

1. 内容から保存先フォルダを決める（迷ったら `00_Inbox/`）

   | 内容 | 保存先 | ファイル名 |
   |---|---|---|
   | スキルの説明 | `10_スキル一覧/` | `<スキル名>.md` |
   | 作業ログ | `20_日報/` | `YYYY-MM-DD.md`（同日は追記） |
   | 調査・決定・手順 | `30_ナレッジ/` | 内容を表す短い名前 |
   | 表現の追加 | `40_表現ルール/` | → `/expression-rules` に任せる |
   | 執筆の記録 | `30_ナレッジ/執筆/` | → `/writing-knowledge` に任せる |
   | その他 | `00_Inbox/` | 内容を表す短い名前 |

2. 同名ファイルがあれば読み、上書きではなく追記または更新する
3. 下のテンプレートに沿って書く
4. 保存後、保存先パスを 1 行で報告する

## テンプレート（新規ファイル）

```markdown
---
title: <タイトル>
type: skill | daily | knowledge | rule | inbox
created: YYYY-MM-DD
updated: YYYY-MM-DD
tags: [<関連タグ>]
source: <きっかけ。会話 / スキル作成 / 調査 など>
---

# <タイトル>

> [!summary] 要点
> 3 行以内で、これが何のメモかを書く

## 詳細

（見出し・表・箇条書きで整理する。長い説明文より表を優先する）

## 関連

- [[関連するメモ]]
```

## スキル説明書の場合の構成

```markdown
## 何をするスキルか
## 起動方法
`/<スキル名> <引数>` の例を 2 つ
## 処理の流れ
## 使いどころ
> [!tip] こんなときに
## 注意点
> [!warning]
## ファイル
- `.claude/skills/<スキル名>/SKILL.md`
```

## 書き方の約束

- コールアウトは `> [!summary]` `> [!tip]` `> [!warning]` `> [!note]` を使う
- 表は 4 列以内にする（Obsidian で横に溢れる）
- 見出しは `##` から始める（`#` はタイトル 1 つだけ）
- 日付は `YYYY-MM-DD`
