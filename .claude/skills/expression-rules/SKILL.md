# expression-rules

ユーザーの好みに合った文章を書くための「表現ルール」を育てる。
使うほど NG リストと良い表現リストが増え、書く文章がユーザーの好みに近づく。

## 保存先（保管庫）の決め方

次の順で決める。最初に当てはまったものを使う。

1. 環境変数 `OBSIDIAN_VAULT` が設定されていれば、そのパス
2. プロジェクトルートに `40_表現ルール/` フォルダがあれば、プロジェクトルート（このリポジトリ自体が保管庫）
3. 隣のフォルダ `../second-brain/` に `40_表現ルール/` があれば、そこ
4. どれもなければ、非公開リポジトリ `michiyosi/second-brain` を `../second-brain/` に clone してから、そこに書く
   - クラウド環境（Claude Code on the web）では、先に `add_repo`（owner: michiyosi, repo: second-brain, access: push）を呼んでから clone する
   - clone できなければ、ユーザーにその旨を伝えて `<プロジェクトルート>/brain/` に一時保存する（公開リポジトリなら注意を添える）

3 と 4 の場合、書き込み後に **必ず `../second-brain/` で git commit と push をする**（`git pull --rebase` してから push）。
コミットメッセージは「brain: <何を記録したか>」の形にする。

## サブコマンド

| 呼び方 | 動作 |
|---|---|
| `/expression-rules add-ng <表現> [理由] [言い換え]` | NG リストに 1 行追加 |
| `/expression-rules add-good <表現> [使いどころ]` | 良い表現リストに 1 行追加 |
| `/expression-rules check <文章 or ファイルパス>` | 文章を NG リストと照合し、該当箇所と言い換え案を表にして出す |
| `/expression-rules show` | 両リストを要約して表示 |

引数なしで呼ばれたら、直前の会話から「ユーザーが嫌がった表現」「気に入った表現」を読み取り、
add-ng / add-good のどちらかを自分で判断して実行する。

## 自動で動くとき（ユーザーの指示がなくても実行する）

- ユーザーが特定の言い回しを否定した（「やめて」「使わないで」「くどい」「AIっぽい」「不自然」「ダサい」など）
  → その表現を **add-ng**。理由はユーザーの言葉をそのまま短く。言い換えは自分で 1 案書く
- ユーザーが特定の言い回しを肯定した（「いいね」「それで」「この書き方好き」など）
  → その表現を **add-good**
- 文章を書く作業を始める前 → 両リストを読み、NG を避け、良い表現を優先する
- 500 文字以上の文章を書き終えた後 → **check** を自分の文章に対して実行し、該当があれば直してから提出する

同じ表現がすでにあれば追加せず、`updated` の日付だけ更新する。

## 追記の形式

### NG表現リスト.md の表（3 列）

```markdown
| 表現 | 理由 | 言い換え |
|---|---|---|
| いかがでしょうか | AI 特有の過剰な丁寧さ | 文末を言い切りにする |
```

### 良い表現リスト.md の表（3 列）

```markdown
| 表現 | 使いどころ | 追加日 |
|---|---|---|
| まず結論から言うと | 説明の冒頭 | 2026-09-03 |
```

### 新規作成時のテンプレート

```markdown
---
title: NG表現リスト
type: rule
created: YYYY-MM-DD
updated: YYYY-MM-DD
tags: [文章, ルール]
---

# NG表現リスト

> [!summary] 要点
> Claude に文章を書かせるとき、使ってほしくない表現。
> 「その表現はやめて」と言われたら、ここに 1 行増える。

## 一覧

| 表現 | 理由 | 言い換え |
|---|---|---|

## 関連

- [[良い表現リスト]]
```

（良い表現リストも同じ構成。summary と表の列だけ変える）

## check の出力形式

```markdown
| 行 | 該当表現 | 言い換え案 |
|---|---|---|
| 3 | いかがでしょうか | 〜です。 |
```

該当なしなら「NG 表現なし」と 1 行で返す。

## 終わったら

追加・更新したファイルのパスと、追加した行を 1 行で報告する。
保存先が `brain/` の場合はコミットして push し、その旨も報告する。
